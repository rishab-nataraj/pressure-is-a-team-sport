# Pressure is a team sport

**SupeRR Selector Season 2, Round 1.** Rank the 10 best batters and 10 best bowlers under
pressure in IPL + T20I cricket (2022-2026), measured against each player's own baseline.

One model explains every batting stint and every bowled over:

```
performance = own baseline + pressure x (player clutch + own-team clutch - opponent-team clutch)

y_s = mu_r + beta_i - q_o + h_s * (c_i + tau_a - tau_o) + eps_s,      Var(eps_s) = sigma^2 / n_s
```

Player clutch `c` becomes **P** and team clutch `tau` becomes **T**, both on a 0-100 scale
(50 = no change under pressure; bottle jobs tend to 0, clutch to 100). P and T are learned
together by alternating closed-form updates (hard EM): what T explains is removed before P is
updated, and the reverse.

* Final lists and every number behind them: [`report/methodology.md`](report/methodology.md)
  (generated by the pipeline) and [`outputs/RANKINGS.md`](outputs/RANKINGS.md).
* Design documents: [`docs/`](docs/) (the project spec and the Jev pressure-data spec this code implements).

## Pipeline

| Stage | Module | Input | Output |
|---|---|---|---|
| 0 canonical IDs | `superr/canon.py` | teams, mapping, matches | `team_canon`, player names, enriched matches |
| 1 state table | `superr/states.py` | ball_by_ball | one row per delivery: score, wickets, balls, target, free hit, partnership, batters (spec section 1) |
| 2 situation calls | `superr/jev_stage.py` | states, standings | wp of every real and hypothetical state (call A), next-ball distribution (B), stakes (C), all cached |
| 3 per-ball fields | `superr/balls.py` | stages 1-2 | WPA, leverage index, pressure, attribution |
| 4 stint table | `superr/stints.py` | stage 3 | batter stints and bowler overs |
| 5 fit | `superr/fit_stage.py`, `model.py`, `tuning.py`, `bootstrap.py` | stints | beta, c, q, tau; CV-chosen penalties; 300 cluster-bootstrap draws |
| 6 rank | `superr/rank.py` | stage 5 | P, T, eligibility gates, two top-10 lists, evidence |
| 7 validate | `superr/validate_data.py`, `validate_model.py` | stages 2-6 | spec section 7 and plan section 11 checks |
| 8 report | `superr/report.py`, `plots.py` | everything | `report/methodology.md` + figures |

`src/00_canon.py` ... `src/08_report.py` run single stages; `python -m superr run all` runs everything.

## Win probability, next-ball odds and stakes: Jev or empirical

Stage 2 needs three situation judgements. Both back-ends see only the situation (score, wickets,
balls, target, format, free hit, ...), never team, player or venue names, dates or match IDs.

* **Jev** (TypeSafe AI's System One model): set `TYPESAFE_API_KEY` and stage 2 uses it automatically.
  * The model version is pinned (`jev.model: jev-1.13.0`).
  * All independent questions about a state go in one request.
  * 429 and 529 responses are retried with backoff.
  * Every raw request, response and answer is cached in `data/jev_cache/jev_cache.sqlite`, keyed by
    sha256(model, state, question).
  * `make jev-plan` estimates requests and cost before spending anything.
* **Empirical** (the default with no key; plan section 12.5):
  * **wp:** monotone gradient-boosted models, cross-fitted by match and Platt-calibrated. Innings 1
    learns from the innings-2 model's win probability at the start of the actual chase, so the two
    halves agree at the innings break. An **end-game solver** does exact backward induction over
    (runs, wickets, balls left) for the last over of each innings.
  * **p_next:** an empirical table by format x phase x wickets band.
  * **stakes:** a Monte Carlo of the remaining fixtures. Series and knockout stakes follow fixed rules.

Choose each slot independently in `config/config.yaml` (`provider.wp | p_next | stakes: auto | jev | empirical`).
For example, Jev stakes with the empirical wp is a valid hybrid.

## Configuration

Every modelling decision is a switch in `config/config.yaml`:

| Switch | Default | Meaning |
|---|---|---|
| `pressure.k` | 1.0 | stakes weight: pressure = LI x (1 + k x stakes) |
| `pressure.theta` | 1.0 | pressure threshold (number or `p75`); h = clip(pressure - theta, 0, h_max) |
| `pressure.h_max` | 3.0 | cap on the pressure dose (`null` = none) |
| `pressure.half_life_days` | 540 | recency half-life for P (`null` = none); T uses all years equally |
| `pressure.li_column` | mean_li | `entry_li` ablation (the batter's own play lowers mean_li) |
| `model.lambda_grid` | 30 ... 30000 | ridge penalties chosen by 5-fold CV grouped by match |
| `model.use_tau` / `use_q` | true | turn team clutch / opponent strength off |
| `eligibility.*` | 20 stints & 150 balls (bat), 40 overs (bowl), 5 recent, delivers, selectable | ranking gates |
| `data.noball_extras` | Overstep, other | `other` is a height no-ball in this pack |
| `data.a_teams_as_parent` | false | fold "India A" into "India" |
| `data.drop_emerging` | false | drop the two emerging / A-team Asia Cups |
| `attribution.bowler_charged_for_byes` | true | false = bowlers judged on the no-bye counterfactual |
| `stakes.bilateral_scale` | 1.0 | down-weight bilateral-series stakes |
| `empirical.endgame_balls` | 6 | end-game solver window (0 = off) |

Override on the command line: `python -m superr run fit rank --set pressure.k=0.5 --set model.use_tau=false`.

## Validation (all produced by `make validate`)

* **Data side** (Jev spec section 7):
  * wp calibration by decile
  * martingale (mean WPA about 0)
  * monotonicity sanity counts
  * real next state vs its hypothetical
  * p_next vs empirical frequencies
  * stakes vs actual advancement
  * a reading of the top 1% leverage balls
  * reproducibility (live re-query of a 1% sample when Jev is used)
* **Model side** (plan section 11):
  * synthetic recovery on the real schedule
  * mover graph
  * 20-seed start stability
  * loop vs single sparse ridge solve
  * out-of-time test (2022-24 vs 2025-26)
  * cluster bootstrap
  * shuffle and sign-flip nulls
  * 14 ablations
  * the CSK claim

The honest headline: as in other sports, the clutch signal is small. The report shows how firm
each top-10 place is (bootstrap intervals and P(top 10)) instead of overstating it.
